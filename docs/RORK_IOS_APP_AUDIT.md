## 1. Security Issues

### CRITICAL: Hardcoded Credentials in Public Repo

**File**: `UrbanManual/GeneratedConfig.swift`

```swift
enum GeneratedConfig {
    static let apiBaseURL = "https://dev-zwpyr282muuhps2yswte1.rorktest.dev"
    static let supabaseURL = "https://avdnefdfwvpjkuanhdwk.supabase.co"
    static let supabaseAnonKey = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

**Risks**:
- Supabase URL + anon key exposed in a **public GitHub repo**
- While anon keys are designed to be used client-side (restricted by RLS), anyone can now make API calls against your database
- The Hono backend at `rorktest.dev` is a development endpoint — unclear if it has rate limiting or monitoring
- If RLS policies are not comprehensive, data could be read/modified by unauthorized users

**Immediate Actions**:
1. Verify RLS policies cover ALL tables (especially `destinations`, `saved_places`, `visited_places`, `trips`, `user_preferences`)
2. Consider making the repo **private** until production-ready
3. Move credentials to build-time configuration (e.g., `.xcconfig` files excluded from git)

### HIGH: Expo Environment Variable Remnants

**File**: `backend/supabase.ts`

```typescript
const supabaseUrl = process.env.EXPO_PUBLIC_SUPABASE_URL!;
const supabaseKey = process.env.EXPO_PUBLIC_SUPABASE_ANON_KEY!;
```

Uses `EXPO_PUBLIC_` prefixed env vars despite being a Swift app. This suggests the backend was initially generated for an Expo/React Native app and was never properly migrated. If these env vars aren't set on the Rork deployment platform, the backend may be **silently failing** and the iOS app falls back to direct Supabase REST calls (bypassing any backend logic).

### MEDIUM: No CORS Protection on Hono Backend

The Hono backend uses `cors()` with default settings (all origins allowed). Any website or app can call the backend API.

### MEDIUM: No Rate Limiting

Neither the Hono backend nor the iOS app has rate limiting. A malicious actor could flood the API.

### Missing Backend Endpoints

These iOS app features have **NO backend support** and either use hardcoded data, on-device processing, or are non-functional:

1. **AI Chat / Concierge** — Uses iOS 26 Foundation Models (on-device) with fallback to basic template responses. Does NOT connect to your Gemini/OpenAI APIs. The web app has `/api/ai-chat`, `/api/concierge/query`, `/api/smart-chat` with sophisticated RAG.

2. **Recommendations** — `RecommendationService.swift` generates recommendations purely from local data (cached destinations). Does NOT use your ML recommendation engine (`/api/recommendations/*`, `/api/ml/recommend`).

3. **Semantic Search** — `SemanticSearchService.swift` appears to do local fuzzy matching. Does NOT use your Upstash Vector semantic search (`/api/search/semantic`, `/api/contextual-search`).

4. **Weather Intelligence** — `WeatherIntelligenceService.swift` uses Apple WeatherKit directly. Does NOT sync with your web app's weather data.

5. **Place Reviews** — `PlaceReviewSheet.swift` exists but there's no API to submit/fetch reviews. The web app has `/api/reviews/summarize`.

6. **Demand Forecasting** — `DemandForecast` model exists but data appears mocked. Web app has `/api/ml/forecast/demand`.

7. **Audio Guides** — `AudioGuideService.swift` expects to download audio from a URL, but there's no audio generation endpoint. The web app has `/api/ai/tts` for text-to-speech.

8. **Collections** — Not implemented in the iOS app at all. Web app has full collection management (`/api/collections`).

9. **Achievements** — `APIService` has achievement-related code but no Hono endpoint. Direct Supabase calls may work if the table exists.

10. **User Preferences / Taste Profile** — Not synced via API. Web app has `/api/intelligence/taste-profile/[userId]`.

### Code Quality Issues

1. **Expo Remnants** — `app/+native-intent.tsx`, `EXPO_PUBLIC_` env vars in backend, React Native entries in `.gitignore`. The app was clearly initially scaffolded as Expo/React Native before being rewritten in Swift.

2. **No Error Reporting** — No Sentry, no Crashlytics, no error tracking. The web app uses Sentry extensively.

3. **No Analytics** — No Firebase Analytics, no Mixpanel, no event tracking. The web app has Vercel Analytics + Google Analytics + custom behavior tracking.

4. **Hardcoded Strings** — Many UI strings are hardcoded in Swift files rather than using `Localizable.strings` for internationalization.

5. **No Accessibility** — No VoiceOver labels, no Dynamic Type support, no accessibility identifiers for testing.

6. **Mock/Placeholder Data** — `DemandForecast` model appears to use mocked data. `MorningBriefing` generates templated editorial strings locally.

7. **Large APIService.swift** — Single file handles all API communication. Should be split into domain-specific services.

8. **No Dependency Management** — No Swift Package Manager dependencies beyond system frameworks. This means no networking libraries (Alamofire), no image caching (Kingfisher/SDWebImage), no analytics SDKs.

### Entitlements Analysis

```xml
com.apple.developer.applesignin       → Default (Apple Sign-In)
com.apple.developer.associated-domains → applinks:urbanmanual.co, www.urbanmanual.co
com.apple.developer.healthkit          → true
com.apple.developer.weatherkit         → true
```

**Note**: Universal Links (`applinks:urbanmanual.co`) require an `apple-app-site-association` (AASA) file to be hosted at `https://urbanmanual.co/.well-known/apple-app-site-association`. This file must be served from the web app. **Check if this file exists on the web app**.

## 5. Recommendations

### Priority 1: Security (Do Immediately)

- [ ] **Make the iOS repo private** until credentials are properly handled
- [ ] **Rotate the Supabase anon key** if it's your active project (project ref: `avdnefdfwvpjkuanhdwk`)
- [ ] **Audit RLS policies** on all Supabase tables to ensure they protect data even with exposed anon key
- [ ] **Move credentials** to `.xcconfig` files or build-time environment injection
- [ ] **Remove Expo remnants** (`app/+native-intent.tsx`, `EXPO_PUBLIC_` env vars)

### Priority 2: Backend API (Before Any iOS Release)

- [ ] **Expand Hono backend** to proxy web app API routes the iOS app needs:
  - Search: `/api/search`, `/api/search/semantic`, `/api/autocomplete`
  - AI Chat: `/api/ai-chat`, `/api/concierge/query`
  - Recommendations: `/api/recommendations`, `/api/ml/recommend`
  - Collections: `/api/collections`
  - Achievements: `/api/achievements/check`
  - Audio/TTS: `/api/ai/tts`
- [ ] **OR**: Point iOS app directly at `urbanmanual.co/api/*` with proper CORS headers for the app's origin
- [ ] **Add rate limiting** to Hono backend (Upstash Redis or similar)
- [ ] **Add CORS restrictions** (only allow iOS app bundle identifier)

### Priority 3: Web App Changes to Support iOS

- [ ] **Add AASA file** for Universal Links: `public/.well-known/apple-app-site-association`
- [ ] **Add CORS headers** for iOS app origin if using direct API calls
- [ ] **Add API key authentication** for iOS app (use existing `/api/account/api-token` infrastructure)
- [ ] **Consider shared API layer** — define a formal API contract that both web and iOS consume

### Priority 4: iOS Repo Quality (Before App Store Submission)

- [ ] Add `README.md` with setup instructions
- [ ] Add `PrivacyInfo.xcprivacy` (Apple privacy manifest)
- [ ] Add `SwiftLint` configuration
- [ ] Add unit tests for models, view models, and services
- [ ] Add UI tests for critical flows
- [ ] Set up CI/CD (GitHub Actions + Xcode Cloud or Fastlane)
- [ ] Add Sentry or Crashlytics for error tracking
- [ ] Add analytics SDK (Firebase or Mixpanel)
- [ ] Add `Localizable.strings` for all user-facing strings
- [ ] Add VoiceOver accessibility labels
- [ ] Split `APIService.swift` into domain-specific services

### Priority 5: Feature Alignment

- [ ] Port iOS-only features worth having on web:
  - Morning briefing (could be email/push notification)
  - Offline mode (PWA service worker already exists)
  - Geofencing (Web Push API)
- [ ] Connect iOS AI chat to web app's Gemini/OpenAI APIs instead of on-device only
- [ ] Sync user preferences/taste profile between web and iOS
- [ ] Add collections support to iOS app
- [ ] Add proper search (semantic) to iOS by calling web API
